# Proposal: SoloPact

**状态：** MVP v0.1  
**日期：** 2026-11-04  
**赛事：** 2026华为开发者大赛·智能体创新赛，OPC组  
**定位：** 一人公司的经营承诺与现金流 Agent；当前 MVP 聚焦合同到回款

## 1. 问题

独立顾问、自由职业者和小型专业服务工作室往往同时承担交付、销售和财务跟进。合同签署后，付款节点散落在PDF中，银行流水需要人工核对，逾期往往在现金紧张时才被发现。通用聊天机器人能解释合同，却不能提供一套可追溯、可复核的应收工作流。

SoloPact 把合同、发票与流水转为结构化应收台账，自动完成候选匹配和风险排序，但把合同确认、模糊匹配和外发沟通保留给用户决定。后续通过经营收件箱接收合同变更、验收结果和客户付款承诺，让邮件真正推动业务状态变化。

## 2. 核心流程

`上传合同 → 确认付款节点 → 导入流水 → 自动匹配 → 发现风险 → 生成催款草稿`

1. 合同抽取：识别客户、金额、日期和付款节点，每个字段保留页码与原文。
2. 人工确认：用户修正抽取结果并确认后，数据才进入应收台账。
3. 流水核对：规则引擎按金额、客户、日期和合同编号计算匹配分数。
4. 风险监测：识别逾期、14天内到期和疑似金额差异。
5. 沟通辅助：生成带合同依据的邮件或微信草稿，必须人工审核，不自动发送。

## 3. 差异化

- **不是聊天记录，而是业务状态变化。** 演示从原始合同推进到已核销回款和待处理风险。
- **规则负责财务状态，模型负责语言。** 非完全一致金额永远不会自动核销。
- **每条结论可追溯。** 付款节点、风险和草稿都回指合同页码和原文。
- **适合一人经营。** 无需部署传统ERP，也不要求用户理解会计科目。
- **外部服务可降级。** 云服务不可用时仍可用演示数据完成完整流程。

## 4. 工程架构

- 前端：React、TypeScript、Ant Design、ECharts
- 后端：FastAPI、Pydantic、SQLAlchemy
- 数据库：开发环境SQLite，Docker与生产环境PostgreSQL
- 文件：本地存储适配器或华为云OBS
- 识别：PyMuPDF数字PDF提取或华为云OCR
- 模型：兼容Chat Completions的模型服务，输出失败时使用确定性模板
- 部署：Docker Compose一键启动

核心实体为 `Document`、`Contract`、`PaymentMilestone`、`BankTransaction`、`ReconciliationMatch`、`RiskAlert`、`CollectionDraft` 和 `AuditEvent`，所有业务实体携带租户边界。

## 5. 已实现与待验证

### 已实现

- 四个工作区及完整REST API
- 合同结构化抽取与人工确认
- CSV/XLSX流水导入和幂等匹配
- 风险规则、证据引用和草稿审核
- 合成演示数据、Docker部署与自动化测试
- 后端10项测试，当前整体覆盖率87%，匹配规则模块覆盖率100%

### 提交前必须完成

- 使用至少10份获得授权的脱敏合同建立字段标注集
- 使用至少30条脱敏流水评估匹配精确率
- 完成3位目标用户访谈和可用性测试
- 补齐华为云真实账号的OBS/OCR/模型服务探针结果
- 录制真实操作视频并收集真实码道使用截图

以上项目在完成前不得写成已经取得的成绩。

## 6. 商业闭环

首批用户为按项目或阶段收费的独立顾问。创始用户价暂定69元/月，价值指标不是“模型调用次数”，而是节省的核对时间、提前发现的逾期金额和缩短的回款周期。

早期获客渠道包括独立顾问社群、自由职业者社区和代账/财税服务伙伴。长期可扩展到应付计划、项目利润和报税资料准备，但不直接提供受监管的财税、法律或投资结论。

## 7. 比赛策略

官方区域赛评分中，功能完备度30分、码道深度使用25分、专业贴合与创新25分、工程质量15分、交付规范5分。因此方案不增加泛化功能，优先保证：

- 三分钟内走完一条稳定主流程
- 展示一次自动匹配和一次金额不符拒绝自动核销
- 展示合同原文证据和人工确认边界
- 码道证据覆盖需求、开发、测试、排错和文档全过程
- 按官方五目录结构提交可复现作品

## 8. 非目标

不做报税申报、复式记账、支付、自动催款发送、投资建议、移动端、多币种汇率核算、区块链确权或复杂团队协作。
